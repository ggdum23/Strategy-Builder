# Packs and the operator sidecar

`backtester.pack` inspects a registered series, optionally anonymizes it, and writes a chunked pack plus an operator sidecar. The sidecar is never placed inside the pack directory. Library code does not print the scale factors. The CLI names the sidecar file and does not print the numbers.

## Anonymized pack

Prices (open, high, low, close, wap) are multiplied by `price_factor` k. Volume is multiplied by `volume_factor`. The source trade count is multiplied by that same `volume_factor`. When the day has a regular (`rth`) session, the daily count is the sum of the scaled bars in that session; otherwise it is the sum of every scaled bar. Both factors are drawn from a log-uniform range away from 1 and away from 0.9 when the operator does not pass them. k of 1 is refused: an anonymized pack has to actually rescale.

Calendar dates become session ordinals starting at 1. The session id is `S00001`, `S00002`, ... The file names are `bars_part_NNN.csv.gz`, `daily_rth.csv.gz`, and `manifest.json`. The manifest calls the asset `RANDOM`. A ticker that matches a reserved report token is refused before any pack file is written. The README lists those tokens. The command exits 2.

The pack files do not contain the ticker, a real year in a file name, an ISO date, the date map, a scale factor, or any digest of a scale factor. The manifest fields are the same set `main` writes, including `pack_id`. The sidecar is the file that stores the factor: symbol, both factors, `share_scale` (the builder writes it equal to k), a random 32-byte key, an HMAC-SHA256 under that key, the ordinal-to-date map, borrow, the source path, and an operator note. The HMAC message is versioned canonical JSON (version 2). It binds `pack_id`, the anonymized flag, the date map, the canonical decimal of k, the canonical decimal of `share_scale`, `borrow_rate_source`, and `borrow_rate_annual`. A null borrow rate stays JSON null. The dividend file is not part of the pack or the sidecar. It is an operator input at run time, so it is not in the MAC. When a run is given that file, the operator `run.json` records the sha256 of the file bytes and `designer/` does not. The date map, which places those amounts on session ids, is in the MAC. Session ids use ASCII digits. A fullwidth digit is neither an anonymized `S#####` id nor a calendar date, on either manifest flag. The anonymized-pack leak scan is separate from that acceptance check. It NFKC-normalizes the file text and maps Unicode decimal digits before looking for a date or a year, so fullwidth, Arabic-Indic, Devanagari, and superscript digits do not hide one. An ASCII number such as a price is not treated as a year.

An anonymized pack is a schema that `assert_anonymized_pack_clean` and `load_pack` share. The directory is read with `lstat` and links are not followed. Every entry is a regular file named `manifest.json`, `daily_rth.csv.gz`, or `bars_part_NNN.csv.gz`. The part number is the builder's spelling: three digits through `999`, then `1000` with no extra leading zero. A symlink, directory, fifo, socket, device, broken link, or any other name is refused, and that error does not repeat the entry name or the link target. The manifest is duplicate-key JSON with no backslash escape, so the raw text and the decoded text are the same characters. Decoded values are typed: `asset_name` is `RANDOM`, `pack_id` is the SHA-256 of the chunk and daily bytes (64 lowercase hex digits, and that exact digest), chunk names are those canonical files, and day fields are the ordinals `1..n`. Each CSV header is exactly the pack columns. There is no free-text column. `session_id` is exactly `S` plus the day ordinal in the builder's spelling (`S00001` for day 1, five digits minimum, no extra leading zero). The bars, the daily file, and the manifest day fields are the same sequence `1..n` with no gap and no repeated session. `time` is `HH:MM` for that row's minute, `session` is `pre`, `rth`, or `post`, weekday is 0–6, flags are 0 or 1, minute is a minute of the day (`00:00` through `23:59`), `bar_minutes` is the manifest's bar size (1 through 1440), and prices, volume, and trade count use the builder's shortest decimal. `pack_id` is the SHA-256 of the chunk and daily bytes, not merely 64 hex digits. On Windows each of those files is enumerated with `FindFirstStreamW`; a stream other than the default `::$DATA` is refused, and the error does not include the stream name. The designer child receives the bar frame read from that default stream. It does not receive the pack directory. `copy_anonymized_pack` is the file handoff: it reads those default bytes and creates new files, so an alternate stream cannot ride along. A number in a price or volume cell may equal a calendar date such as `20240102` or an epoch such as `1704067200`. It is still a scaled print. It carries no ticker, and rejecting it would also reject a real print, so the gate allows it. A `date_map` key is a canonical ordinal (`0` or digits without a leading zero). The key and the MAC stay in the sidecar. The operator child receives `share_scale` so the real invoice can use real share counts. The designer child does not. That split is described below. The sidecar is not copied into either child. The strategy file runs in the referee jail and is not given the sidecar, `factor_key`, `factor_mac`, or k. A sidecar with no MAC is refused, named or anonymized, and has to be rebuilt. Verification accepts only MAC version 2. A version-1 tag, including one recomputed with the sidecar key over the version-1 message, is refused, and that pack has to be rebuilt. `load_pack` refuses an `S#####` session id unless the manifest says anonymized. The stand-in asset name `RANDOM` is the same kind of marker.

A named pack is the other switch. It keeps real dates and forces every factor, including `share_scale`, to 1. The CLI makes the choice explicit: `--anonymize` or `--named`.

## Chunks

The target is about 250 trading sessions per file, and every file stays under 25 MB. A single session that does not fit is an error. A session is never split across files. Gzip members are written with mtime 0 so two builds of the same rows hash the same.

Bar size is fixed when the pack is built. `run --pack` does not resample again. Build another pack to change the bar size.

## Two cost models

Prices times k means the builder writes `share_scale` = k. Pack share counts are about 1/k of the real count. Every anonymized run goes through `run_pack` or `walk_pack`. The parent reads the sidecar, then drops the document before either child starts. Neither child receives the sidecar, the date map, the ticker, the volume factor, or the operator note.

The operator child is the real invoice. Per-share fees (commission, the monthly tier count, exchange, clearing, CAT, TAF) use real share counts: `abs(pack shares) * share_scale`. Value-based fees (SEC, and the commission and clearing caps) use pack shares times pack price, which is the real trade value. `fee_mult` is still the Desk stress switch and does not scale borrow, financing, or the tier count. The loader checks the operator HMAC before it uses the sidecar price factor and before it compares `share_scale` to that factor. The MAC covers the pack id, the anonymized flag, the date map, and the borrow rate as well as those two scales. An anonymized sidecar whose `share_scale` is not the build-time price factor is refused. The builder writes `share_scale` equal to k.

The designer child is a second process. It uses the flat fee in `docs/COSTS_DESIGNER.md` and the canonical $1,000,000 index. It is not given `share_scale`, `share_factor`, or the operator account size. There is no per-share commission and no per-share SEC or TAF on that run. The same flat constant applies to every ticker.

`metrics.json` next to the report is the operator book. It records the cost basis that was used: share scale, profile, schedule, and that per-share fees were real share counts when `share_scale` is k. The report does not include the date map or the volume factor. `cost_comparison.json` is also an operator file. It places the real-fee result beside the designer-cost result and the difference (designer minus real). The difference omits `final_equity`. A designer audience of a pack walk reads `designer/metrics.json` only and does not include the operator design or locked returns.

An anonymized run also writes `designer/`. That directory is the copy to hand a strategy designer. It has no ticker, no calendar date, and no scale-factor field. Equity in that tree starts at the canonical index, so the dollars do not follow the real account. The label on those metrics is `designer cost model: 0.8 bp flat`. A parallel batch does the same split: operator files under `jobs/`, and one designer bundle under `designer/` with the leaderboard and each anonymized job. The designer leaderboard is ranked on the designer-cost excess, not the operator excess. Hand over that `designer/` directory only.

If the series borrow was recorded as the profile default, the run uses the borrow rate of the profile you select. One pack can be run on Arena and on Desk. An explicit borrow overrides both.

Dividends are real dollars per real share, keyed by calendar date. The operator child receives each amount multiplied by `share_scale`, remapped through the sidecar date map to the pack session id (`S00001`, ...). The designer child receives each amount multiplied by the build-time price factor k (the factor whose operator HMAC matches, not `share_scale`), remapped to the same session id. A date that is not in the pack is an error. Dividends are not written into the pack. Neither child receives a calendar key. An anonymized pack walk stamps `cost_basis.anonymized` on the operator design and locked books. A named walk leaves that flag false.

## Residual leaks

These are the leaks the plan already names. Scrambling further does not remove them, and this builder does not pretend to.

- Weekday plus early-close and holiday gaps can be lined up with a real calendar. Weekday stays in the file because the engines and the strategies receive it. The ordinal calendar hides the year. The shape of the week stays visible.
- A crash-shaped return path is recognizable without a date.
- Native tick times `price_factor` can reveal the scale, because the price grid is still a grid after a constant rescale.
- The exact-equity plus per-share-schedule residual is closed on designer surfaces. A designer run has no per-share term, is not given `share_scale`, charges one fixed basis-point constant, and reports equity on the canonical index. The jailed strategy is not given the sidecar, `factor_key`, `factor_mac`, k, or `borrow_rate_source`. The operator worker still receives `share_scale` and still bills the real schedule. The sidecar MAC is checked before that scale or the price factor is read. Post-fee cash on the operator book can still be read against that schedule. That book is not handed to a designer.
- The designer tree keeps exact equity on the canonical index and charges the flat fee. Fees are a cost drag in basis points of that book's equity, `fees_total / initial_equity * 10000`, rounded half-up to 0.1 bp. A designer-visible strategy id matches the allow-list grammar (a leading letter, no four-digit run, no month or calendar token). A decimal is not an id. An id that passes is not scanned as a price. The scan still applies the scale, the ticker, and that grammar, and a rejected id fails that one job under an opaque name. `publish_designer` scans that tree with the operator scale. A scale or a price left in the text removes `designer/` and the publish fails. The designer chart is rewritten to critical PNG chunks. A `pack_` hex source id is stored as an opaque id on that tree. The operator copy keeps the original id. `factor_key`, `factor_mac`, the price factor, and `borrow_rate_source` stay off this tree.
- Bar `count` is the source trade count multiplied by `volume_factor`. When the day has a regular (`rth`) session, the daily count is the sum of the scaled bars in that session; otherwise it is the sum of every scaled bar. The gate checks that sum. A pre or post cell on a regular-session day is not part of the sum, so a date-shaped count can still sit in that cell. The source integer is not copied. A constant rescale leaves an arithmetic progression as a progression, so consecutive source counts still determine the factor from their gap. That is the same kind of residual as a price grid revealing `k`. The raw integer is not in the file.
- A price, volume, or trade-count cell is the decimal the builder writes. An integer such as `20240102` can be a real scaled print. The gate does not treat that number as a date. `session`, `time`, and `session_id` are not free text: `session` is `pre`, `rth`, or `post`, `time` is the row's `HH:MM`, and `session_id` is the ordinal above. A string such as `S202401021` or `S946684800` is refused because it is not that ordinal. Manifest strings are the fixed schema (`RANDOM`, `raw` or `total_return`, canonical file names, and the content hash). The other integers are bounded or derived: weekday `0..6`, minute `0..1439`, flags `0` or `1`, `bar_minutes` `1..1440` and equal to the manifest, `schema_version` `1`, and the day fields the sequence `1..n`.

Mitigation is the rule set (no identification, no external market data, no sidecar in the designer tree) plus the schema gate, not another hash of the prices. `assert_anonymized_pack_clean` and `load_pack` share that gate: a regular file with a builder name, a typed manifest, and a typed cell in every column.
